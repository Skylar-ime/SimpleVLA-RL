# 阶段B v4：SDPO对齐的丰富反馈实验

## 为什么v3的控制元素无法区分

v3 的结果没有建立 SDPO 机制。其保存的产物显示了四个混杂因素：

1. `2306/2560`结果反馈行是一样的`(no contact, no motion, unchanged, failure)`元组，因此名义上富有的条件几乎没有任何可变的信用信息。
2. 老的混乱控制保留了尝试和成功。因为主导反馈元组在大多数行中共享，只有`17.54%`行被重新排序。
3. 每个安全过渡进入蒸馏，包括没有有意义环境后果的行。原始SDPO仅在成功同伴演示或非空环境反馈可用时启用其自蒸馏掩码。
4. 飞行员使用对称JS和当前策略作为独立教师。发布的丰富反馈运行使用反向KL(`alpha=1.0`)和一个独立的EMA老师，更新率`0.01`.

观察到的共同趋势向行动A是与通用的重提示/提示长度偏见一致，而不是对正确丰富反馈的语义使用。

## V4更新

- 五步分布蒸馏与反向KL匹配SDPO`alpha=1.0`在这个飞行员的完整动作空间。
- 将可训练的LoRA权重的EMA副本与更新率分开`0.01`.
- 重试掩码仅限于失败尝试，其中测量接触、物体运动或非零分类进展。
- 一步独立部署重置，以防止后续对象动作削弱反馈。
- 更长的方向场景(`0.13-0.16 m`目标距离)所以，一个有用的第一次推送通常会带来积极的进展，而不会立即完成任务。
- 连续测量字段：有符号进度、立方体位移和目标距离前后。
- `hard_shuffled`控制总是在可用时选择不同的跨会话记录。
- `result_interpreted`ARM 只将模型尝试执行的动作和测量的结果翻译成保留/拒绝的措辞。它从不提供专家或反事实行动。

## 教师机制门

在32个固定方向的开发场景中，模型的事实反馈老师仍然减少了四个口罩合格尝试的预期反事实进展。`1.91 mm/step`. 翻译后的反馈教师增加了它。`3.36 mm/step`二进制、硬洗牌和中性反馈降低了它`3.75`, `3.33`并且`3.11 mm/step`分别。

这是一个本地诊断，而不是效果声明：只有四次尝试是口罩合格的，并且所有场景的启动间隔跨越零。这足以证明v4在线比较的有效性，其开发评估仍然独立进行，测试分割也尚未公开。
