# V7 SDPO-对齐的丰富反馈实验

## 为什么早期条件无法区分

早期的结果并没有表明丰富的反馈没有价值。它有四个混淆因素：

1. V5 使用独立过渡，因此老师没有相同状态的自我生成的成功解决方案。它衡量的是条件反馈的动作变化，而不是原始的SDPO训练循环。
2. V6 称积极一步进步为成功的解决方案，尽管模拟任务结果仍然失败。这改变了 SDPO 成功掩码。
3. V6 增加了结果反馈，并附带了解决方案。检查过的 SDPO 配置使用`environment_feedback_only_without_solution`所以，反馈仅在没有成功自动生成解决方案时使用。
4. V5和V6优化的反向KL。检查的SDPO配置使用`alpha: 0.5`，这是Jensen-Shannon扩散。六到八次更新，一个种子，一个64场景的发展评估，以及一个专注于A/C的策略进一步降低了功率。

## V7对齐

每个组包含从一个精确初始图像和机器人姿态中采样的八个候选动作。兄弟候选是一个解决方案，只有当其测量的模拟器结果是实际任务成功时才被视为解决方案。该候选本身不作为自己的解决方案来源。对于有兄弟解决方案的行，反馈被抑制并用于没有兄弟解决方案的行，以匹配SDPO掩码和提示构造。

学生只看到原始图像、指令、本体感受和动作查询。老师看到相同的原始状态加上一个成功的兄弟行动和/或回顾性反馈。教师概率由一个单独的LoRA EMA教师计算，并在优化器步骤之前缓存并分离。训练每批滚动使用JSD进行一次优化器步骤。`alpha=0.5`; GRPO和行为克隆损失为零。

本地方向场景描述使一个正确的推力能够完成任务。这给一步飞行员真正的成功自动生成解决方案，而不是重新标签积极进展。这是一个机制测试，而不是关于全范围操纵的声明。

## 条件

- `sdpo_result`测量接触，运动，有符号的进步，距离和成功。
- `sdpo_binary`成功判决。
- `sdpo_shuffled`测量结果来自另一个状态，使用相同的尝试动作和成功层次；同状态的捐赠者被禁止。
- `sdpo_neutral`: 无测量字段，用于作为中性提示控制。
- `sdpo_causal`测量结果加上明确的保留或修订解释。这是对原始测量反馈的解释删除，与原始测量反馈无关。

主要比较使用`sdpo_result`对抗二进制、打乱和中性。报告必须包括解决方案覆盖、反馈使用覆盖、教师分布变化、行动覆盖、每次更新评估以及在任何效果声称之前的变化限制。
