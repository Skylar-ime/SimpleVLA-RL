# SDPO 机器人结果反馈快速验证方案

日期：2026-09-25。状态：阶段B v1 与近距离机制诊断 v2 已完成；未达到进入阶段C的机制门槛，测试仍未开启。

## 1. 目标与结论边界

主问题：在不提供纠正动作、成功示范、专家标签、额外奖励损失的条件下，当前视觉语言策略是否能利用自身动作的可观测执行结果，通过反馈条件化自蒸馏，提升无反馈部署策略的控制能力？

首先验证机制，然后验证大模型和复杂机器人任务上的泛化。第一轮不宣称优于 GRPO、不宣称解决长时域信用分配、不宣称提升 OpenVLA 或真实机器人性能。主结果必须来自有物理仿真、真实 RGB 输入、闭环控制的实验，不能用文本网格游戏或状态向量实验替代。

本方案采用 Qwen2.5-VL-3B-Instruct + panda-gym/PyBullet + 5 类单token平面末端运动策略。它是小动作空间的视觉语言机器人控制器，不是预训练的低层通用VLA。选择它是为了减少基础设施和分布蒸馏难度；其机器人控制及反馈理解能力尚待试点检验。

现有的 SimpleVLA-RL 和 SDPO 目录保持不变。新的实验独立开发，不启动远程 GPU 作业。

下一轮开发修复 `directional_push`单独冻结：目标相对物体只取四个轴向，初始末端执行器位于物体背向目标的 4.5--5.2cm 近接触位置，所有反馈组共享完全相同的公开初始状态分布，观测与 teacher 仍不提供正确动作标签。6.5--7.5cm 版本的物理探针已失败：128 个场景、640 个动作全无接触。调整距离后的物理探针已通过：128/128 reset 有效；C/D 接触率 28.9%/24.

## 3. 主任务：PandaPush 平面局部推物

### 3.1 场景

基于PandaPush-v3构建明确命名的自定义wrapper：`PandaPushOutcomePilot-v0`。不能将其结果当作原始的 PandaPush-v3 成绩。

- Franka Panda、桌面、4厘米方块、可见目标标记。
- 夹爪闭合且固定，末端保持固定姿态，动作只改变水平目标位置。
- 方块初始 xy 在中心 16 cm × 16 cm 区域采样。
- 目标距离方块初始位置为 10–14 cm，方位角均匀采样；超出预注册工作区的场景重采样。
- 末端从方块周围一个独立均匀方位角初始化，初始中心距离参考 5.5–8.5 cm；方位角不根据目标位置选择。
- 接触高度必须根据 Panda 末端碰撞几何进行无目标校准，不能把方块中心高度直接当作末端 link 高度。校准后记录实际`ee_z_m`、关节姿态和碰撞体间隙，再冻结协议。
- 初始化和固定时间后若未能成功，则不得与方块相互穿透，且不得出现超过2mm的无动作方块漂移；拒绝条件应一致，并记录拒绝比例。
- 不要通过规划器选择“有利推动侧”。初始化是一个共同的任务设置，而不是给演员的解题动作。

安装一台能看见末端、方块和目标的相机，建议使用 448×448 RGB、俯视斜角。相机外参在开发集中校准后冻结。可以叠加固定的 +x 和 +y 轴投影图例；投影必须由同一相机矩阵生成，不能手动绘制一个近似的箭头。不要叠加动态目标方向、最佳动作或隐藏状态坐标。

### 3.2 统一动作契约

动作标签候选为 A/B/C/D/E，含义分别是世界系 +x/−x/+y/−y/保持。必须验证在真实 chat template 的回答位置，每个候选都是不同的单 token；若不满足，换标签并冻结映射，不能将多 token 字符串的首 token 概率当作动作概率。

期望的最终目标增量为 2 cm。Panda-Gym 的末端接口在源代码中将输入乘以 0.05 m，因此候选动作输入分别为`[0.4,0,0]`、`[-0.4,0,0]`、`[0,0.4,0]`、`[0,-0.4,0]`、`[0,0,0]`。

一次决策只调用一次 `robot.set_action(action)` 设置目标，再保持该目标推进 4 个 `sim.step()`源码默认每次 sim.step 为 20 个 0.002 秒物理子步，因此一次决策名义持续 0.16 秒。**禁止重复调用四次 env.step(动作)，那会四次累加目标位移。**2厘米是目标增量，不保证实际移动2厘米；记录实际位移。

所有动作，包括保持，都推进相同的仿真时间。每个 0.04 秒区间记录接触事件，反馈在完整 0.16 秒末读取。成功在决策末判断，不在中间停步。最多 32 次决策，即最多 5.12 秒模拟时间；墙钟时间另计。

成功标准是方块中心到目标中心的三维距离严格小于 0.02 米。官方的 Push 默认阈值为 0.05 米，本实验明确改为 0.02 米。当距离恰好等于阈值时失败，反馈、终止和评估调用同一谓词。不使用环境奖励数值构建 SDPO 损失。终止包括成功；越界或严重仿真错误单独记为安全失败；32 步为超时截断。

任何边界裁剪都必须是共同、固定的、与目标物体无关的控制保护，并记录请求/应用的动作。不要仅仅对教师候选人进行安全筛选。

## 4. 仅结果反馈：允许与禁止

对每个真实执行的决策，收集 `(o_t, a_t, o_{t+1}, f_t)`。反馈是以当前动作的实际后果为单位的，而不是生成整个episode的因果故事。

主反馈字段：

- `contact`: 在这个决策区间内，机械臂末端是否会与方块发生接触；根据碰撞体ID进行判断。
- `object_motion`: 方块在xy方向上的位移是否超过统一的噪声阈值。
- `goal_progress`动作前后方块到目标的距离变化为更近/不变/更远。
- `success`: 决策结束时是否达到任务目标。

定义 `progress_m = distance_before_m - distance_after_m`大于正阈值为 closer，小于负阈值为 farther，其他为 unchanged。初始阈值 0.002 米，必须先用无动作静置样本校验；若噪声超标，在开发阶段依据噪声统一调高并重新生成全部组的反馈。`object_motion` 同样使用校准后的阈值。

文本模板只输出观测结果，例如：

```text
Attempted action at the original observation: C.
Observed result after execution:
Contact with the cube: yes.
Cube motion: detected.
Distance to the target: increased.
Task completed: no.
```

不提供“应向右”、“减小力度”、因果诊断、精确期望末端姿态、最优动作、专家轨迹、其他成功滚动。`goal_progress`这是事后目标相关的测量，包含比二进制成功更多的信息，应如实称为“仿真真值导出的结果反馈”。它不是现实部署已经具备的免费传感器。

仿真状态仅供编译器和评估器读取，actor 输入不得包含方块/目标真值坐标、进度数值或反馈。规则编译器不能计算反事实最优动作。后续可以另做感知估计反馈或去掉目标。_消融的进展。

## 5. 政策与教师输入

学生 输入：当前的 RGB、任务指令、固定动作定义、可选的实际末端 proprio xyz。如果使用 proprio，单位为 m、世界坐标，所有组相同。图像必须是决策前的图像，而不是动作执行后的图像。

老师 输入：同一个决策前 RGB、同一指令和 proprio，加“该状态上尝试的动作与实际结果”。末尾固定说明：

```text
Choose the action for the ORIGINAL image/state, not for the post-action state.
Return exactly one action label.
```

这可以避免将回顾性评估误认为是从失败后的状态恢复。它不能保证模型理解正确，需要通过探针验证。

每个教师对照都包含相同的 attempted-action 字段，以避免正确反馈组独享额外动作信息。中性组用于分离由于重复原动作导致的自我复制效应。

只读取回答起始位置上 5 个已验证标签令牌的 logit，并在同一集合内进行 softmax。rollout、teacher、student loss 使用完全相同的动作集合、排列和温度 1.0。此分布是显式定义的 5 类策略，而不是完整语言词表的近似 KL。无需生成思维链、JSON 或长文本。

## 算法：单轮冻结的当前自教师

每轮开始参数为 θ_K。在无反馈条件下从该策略采集256个真实过渡；期间不更新参数。随后使用相同的theta_K，在正确/对照反馈条件下_计算并缓存每条记录的 5 维教师分布 q_K。然后重新计算学生分布并累积完整的批次梯度，只进行一次优化器步骤。下一轮使用新的θ。

这是实现当前策略的反馈自蒸馏，不需要第二份 3B 模型，也不是冻结初始 checkpoint。第一版不引入 EMA、信任区域、参考 KL、熵奖励、GRPO 或行为克隆。它是 SDPO 基础机制的最小变体，不能称为复现了论文全部稳定化配置。若不稳定，EMA 只能作为第二个明确版本，所有对照同步变更。

让 p_θ(一个|x)对于学生5类分布，q_好的，我将把Markdown文本翻译成简体中文。请提供需要翻译的Markdown内容。(一个|x, a_取走，拿走)为了缓存的教师5类分布，M=(p 加 q)/2。

`loss = mean[0.5 * KL(p || M) + 0.5 * KL(q || M)]`。

停止梯度，M 中的 p 仍保留梯度。使用 FP32 计算对数。_softmax/logsumexp 计算概率与 JS，模型前向可 BF16。不是只惩罚原先采样的那一个动作。无效传感记录才 mask；不能因为所有动作失败就过滤。第一次优化前 student 与采样策略一致，第一版不做旧批次多轮重放，也不加入 PPO 比例。

训练参数起点：LoRA rank=8、alpha=16、dropout=0，仅语言解码器注意力的q/k/v/o投影，视觉编码器、视觉投影器和基础权重冻结。实际模块路径以模型命名_模块验证，避免误将视觉模块包含在内。AdamW lr=2e-5、权重_衰减=0、梯度_clip=1，微批次=4。每轮预算固定为256次实际决策执行，损失以其中有效样本数归一化。无效记录mask，不额外补采，不从交互计数中删除；整批无效则跳过优化并记录。无效比例异常时停止排查，不能以补采掩盖各组不同的交互成本。

模型保持评估模式以禁用dropout，但学生前向必须启用自动微分；评估不等于无。_Grad。所有教师分布必须在第一次参数更新之前生成。LoRA的adapter、processor和action map一起保存。

## 7. 必需对照

首轮最小比较包含冻结初始策略和三个独立训练组：

1. `frozen`：无训练、无反馈部署。
2. `result`：纯SDPO，真实结果反馈。
3. `binary`：纯SDPO，只保留动作后的success，其余槽位为未报告。
4. `shuffled`：纯 SDPO，保留当前 attempted-action 与 success，但其他结果字段替换为其他轨迹的记录。

开发诊断 v2 增加`neutral`，并使用 `mechanism_near_contact`场景：目标仍然随机，末端相对于方块的方向仍然独立于目标方向；仅将初始末端距离缩短至4.4-5.2厘米，将结果信息密度从阶段Bv1的约3.5%接触率提高。此修改不提供动作标签、纠正动作或目标方向先验，不得与标准任务结果合并。

V2 结果（单种子、开发集，不是最终效果结论）：五组均请求了64个场景，其中54个有效重置、10个因机器人与物体重叠而被拒绝；五组均无成功结果。`result`组训练接触/运动比例均为 8.125%，教师相对于学生有非零分布漂移，但贪婪动作仍几乎全为 A。在无反馈部署下`result`相对于冻结的平均进度仅增加了 0.000122 米；相对于二进制、打乱和中立差异接近于零。因此不启动阶段 C，也不打开测试。首先修复任务与策略动作的可识别性并降低无效重置，然后用开发预注册验证；不得据此断言 SDPO 在机器人中无效。

在同一个训练分割、尝试动作和成功记录池中进行打乱，禁止取本episode；不匹配原始状态和原始结果。字段整体打乱，不能将接触、位移和进展独立打乱成逻辑不可能的组合。记录捐赠转移ID、实际改变比例和未匹配比例；未匹配则该条退化为二进制，并在汇总中披露。

如果“无动作/未接触”占据多数且打乱后几乎不变，则对照组缺乏辨别力。应扩大训练结果池或增加样本，不能将“shuffled≈result”作为无效或有效的反馈证据。不能从测试池中选取捐赠者。

模板使用固定字段；相同的微批次统一填充到已验证且不截断的长度（建议文本上限为384个令牌，视觉令牌另计）。二进制语义信息必然较少，但不能让它少一次教师前向传播。记录真实的令牌数和耗时，不声称填充消除了所有计算差异。

资源允许时必须补 `neutral`：相同的尝试动作，所有结果字段中的 success 都未报告。这隔离了纯粹的 prompt/self-copying 作用。`result`只有相对二进制和打乱都有优势，才是最小机制的证据；仅仅优于打乱是不够的。

第一轮不跑 GRPO，避免调参和系统成本。若后续声称 SDPO 优于奖励塑形，还必须增加使用相同结果字段的 dense-reward RL 基线；本实验本身不能支持该结论。

## 8. 数据划分与预算

首先生成并保存固定场景的 ID 和完整的重置参数，然后采样轨迹。空间范围相同但实例独立：训练集 2048、开发集 128、测试集 256。场景包括物体位置、目标位置、机器人初始姿态、相机版本和物理参数。ID 和实际参数均需去重；仅更换整数种子不被视为充分隔离。

训练轨迹及捐赠池只来自训练。提示、相机、接触高度、阈值和学习率只能在开发中调试。测试在协议冻结后一次性打开，不用于筛选任务、选择检查点或修复提示。

主要训练 seed 为 11/22/33；分别控制 LoRA 初始化、动作采样、环境采样和 shuffle 随机流。各组配对使用同一 seed 和 reset 调度，但动作不同导致后续状态不同是在线训练的正常结果。实际交互预算相同，不能要求在线组共享全部轨迹，否则改变了 on-policy 定义。

### 阶段A：契约与反馈探勘

- 先做20个场景的动作映射/相机/反馈烟雾测试。
- 从开发人员的128个不同场景中，随机选取一个决策状态，并观察该初始策略在该状态下尝试后的结果。
- 在相同状态下比较 p、q_结果、q_二进制、q_洗牌的动作分布。
- 可恢复原状态，枚举 5 个候选动作，测量局部 `distance_before - distance_after` 和安全失败。
- 将每个策略的概率加权到这些反事实结果上，得到配对的预期局部进展差异；这些结果仅用于诊断，不输入教师，也不作为训练标签使用。
- 枚举最多 640 次候选动作执行，单独计入探针成本，不藏入训练预算。
- - 状态ID仅在同一个进程中有效。恢复还需要覆盖任务目标、包装步骤、RNG、控制器缓存和电机目标；首先验证相同动作重放的误差。持久化使用场景参数、轨迹前缀、状态序列及其版本，而不是仅仅存储一个整数句柄。

这个探针不需要老师先完整完成任务；零局部进展也可能来自延迟的物理效果。先看接触、进展方向等指标，不要把单步距离指标当成全局最优动作标签。

### 阶段B：快速试点

- 结果/二进制/打乱 三组，各 1 个种子、10 轮、每轮 256 个转换：每组 2560，共 7680 次训练交互。
- 仅在dev上评估；作为开发实验，不能将其dev结果包装为最终测试结论。
- 检查正向反馈是否产生了非零、合理的梯度，学生是否有所改进，以及打乱是否有足够的变化。
- 如果需要调整参数，只能在预注册的范围内进行小范围的共同修改，并重新运行三个组；不仅仅是优化结果。

### 阶段C：最小可报告结果

- 冻结协议后，每个训练组各有 3 种种子 × 60 轮 × 256 个过渡。
- 每个 run 15360，9 个 run 共 138240 次训练交互。
- 每隔 20 轮进行 dev 中的固定 64 场景评估；主指标使用最后一轮模型，不挑 test 最优。
- 最终每个模型在同一个 test 256 场景下进行一次无反馈 greedy rollout，最多 32 步。
- 冻结的初始模型根据相应的种子进行评估；如果初始LoRA为零有效更新且策略完全相同，则只评估一次并共享结果。
- 学习曲线使用dev，最终效果使用test。训练交互、诊断交互、开发评估、最终测试成本分别统计。表述中的每轮256个transition是执行预算，包含已执行但被mask的异常记录，必须另报有效记录数。

当前测试规模为探索性规模，不保证能检出5个百分点的小效应。如果区间很宽，结论必须写“不确定”，而不是“不存在效果”。

## 9. 主要指标、统计与判定

主要指标：无反馈测试成功率。核心预注册对比是result-binary与result-shuffled。

次要指标：末端/物体安全失败率、最终目标距离、首次接触与有效推动率、动作熵、同一输入上的学生KL漂移、反馈字段分布、shuffle改变率、JS、梯度范数、GPU峰值显存、每过渡墙钟成本。

使用相同的种子和相同的测试场景进行计算差异，并报告每个种子的差异以及平均差异。对种子和场景进行分层/交叉重采样，保持方法间的配对，生成探索性区间；三个种子的种子级不确定性很大，不将数百条episode视为数百次训练重复。如果要做两个正式的显著性检验，需要预先注册多重比较控制；第一轮主要关注效应量和区间。

工程继续投入的阈值可以预先设定为：结果相对于二进制和打乱平均至少提高5个百分点、至少三分之二的种子为正、安全失败未增加。这个阈值只是资源决策的标准，不能替代统计证据；即使跨越零点也属于初步信号。

失败解释：

- 正确的反馈教师行为系统性较差：检查坐标、输入时间、反事实问题和地基，最多进行预注册的有限开发修正；否则报告该模型/任务组合不适合作为快速验证起点。
- 老师没有可测量的整体任务收益，但有局部判断的变化：仍然可以运行短的试点。
- 正确的反馈和二进制同样有效：只能支持“结果信息有帮助”，不能支持丰富的反馈超过二进制。
- 正确的反馈优于错误反馈，但不优于冻结/二进制：无法证明学习机制的有效性。
- KL 降低但没有反馈测试没有改善：只能证明分布被匹配，不能声称控制能力提升。
- 测试不改善且置信区间宽：样本或预算不足也可能解释，不得推断 SDPO 在机器人上无效。

增加视觉地基检查：在开发中遮挡物体/目标或替换图像，确认策略对视觉条件具有合理的敏感性。如果完全不依赖图像，则不能称为视觉控制证据。此检查仅用于评估，不生成训练目标。

## 10. 快速实施与耗时管理

候选硬件：一块 24–48 GB 的 GPU 加上 8 个 CPU 仿真进程；这是待测配置，而不是显存保证。模型 BF16、LoRA、冻结视觉模块、每张图片 448×448、一个输出 token。首先使用 microbatch=1 验证峰值，然后提升到 4；不能将梯度累积与 GPU 并行批量混淆。

不需要 Ray、vLLM、FSDP、critic、第二份 teacher、外部 LLM API。teacher 在更新前缓存为每 transition 5 个 FP32 概率即可。图像预处理结果可重用；多模态 position IDs 和 attention masks 必须分别由各自 prompt 重建，不能强行复用 student 的文本位置。

先做 256 次过渡的端到端计时，分别记录采样、渲染、反馈、教师前向、学生反向和评估。定义 c 为训练所有阶段的实际总秒数除以 256；单次运行的训练估计为 15360×c，完整训练为 138240×c，另外加上下载、启动和评估。

仅作为算术示例：如果实测c=0.2秒，9个run的纯训练大约需要7.68小时GPU时间；如果c=1秒，大约需要38.4小时。这两个都不是实际测量结果。如果超出预算，先运行阶段B，不要悄悄减少测试或种子，并继续使用“确认性结论”的措辞。

初版开发工作按顺序拆为：

1. `env_adapter.py`: 共同重置、动作映射、时钟、终止、反馈原始测量。
2. `policy.py`处理器、五类令牌分布、LoRA、无反馈滚动。
3. `feedback.py`：确定性事实模板、二进制/打乱/中立；不调用策略求解器。
4. `train.py`冻结参数采样、缓存教师、累计JS、一次更新。
5. `evaluate.py`：无反馈评估、配对场景ID、探针恢复。
6. `report.py`：根据种子和场景进行配对统计，成本与失败分类。

这些是待实现模块，不存在可直接运行的训练 CLI；本交付不伪造可运行命令。不要为第一轮先开发复杂数据集管道或远程多卡调度。

## 12. 实现验收清单

- 五个标签令牌唯一，rollout 和损失的动作支持集/温度一致。
- 2厘米是目标位移，0.16秒是一项决策时间；不采取行动也会消耗时间。
- 接触、进展、成功都源自同一对齐的过渡；边界条件、单位一致。
- 不存在使用目标位置的动作宏、专家热启动或成功轨迹检索。
- 学生没有结果反馈；老师只增加该状态的原始动作结果，不替换图像。
- 五种JS与手动分布一致；当p=q时，损失/梯度接近于零；教师没有梯度。
- 完整的批次只进行一次优化步骤，微批次划分不会改变归一化。
- 没有反馈和完全相同的提示的数学对照应接近于零梯度；中性改变了提示，就不能要求零梯度。
- 老师 每轮来自当前策略，下一轮刷新；未冻结在初始 checkpoint。
- 修改 reward/GRPO 优势数组不会影响 SDPO 梯度；在实现中最好不要读取这些字段。
- 打乱后，有捐赠者审计且不跨越分组；正确的反馈不仅对成功或“好样本”启用。
- 恢复覆盖物理状态和Python状态，重复执行误差在已记录的容差范围内。
- 测试策略没有反馈、没有老师、没有参数更新；配对报告和真实预算可以追溯。

这些是未来代码和实验的验收项，不是已经通过的测试。当前完成的是源代码核对、方案和参数记录。

## 13. 升级路线

如果阶段C获得机制证据，先补充中性并移除目标_进展：消融，并非由“进步”信号造成的假象。随后迁移OpenVLA单步离散动作接口，在原任务checkpoint上运行相同的result/binary/shuffled/frozen对比；保持原checkpoint的输入、动作归一化和评估口径，不随意切换OFT或混入GRPO。

第二个物理任务可选PickAndPlace，但接触、抓取、物体随动反馈需重新校准。长程credit assignment、EMA teacher、真实机器人感知反馈、成功示范与纠正建议分别作为后续实验。若只完成小动作空间实验，最终报告必须保持相应结论边界。
